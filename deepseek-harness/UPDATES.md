# 面对持续更新的学习方法

每课的解释都有版本依据。首个基线是 `0.1.6-alpha.2`、提交 `ddefc45fbc7f8e46dd73185e68295696d1297887`，采集于 2026-09-20。它表示本机当前检出的版本，不表示上游最新版本。

## 继续学习前

在学习仓库运行：

```powershell
node .\deepseek-harness\tools\check-source.mjs
```

换一份源码目录时：

```powershell
node .\deepseek-harness\tools\check-source.mjs --source "D:\another\deepseek-harness"
```

脚本读取 [SOURCE_BASELINE.json](SOURCE_BASELINE.json)，比较已关注目录的提交差异、未提交变化和关键文件 SHA-256。它只读本地，不联网，不拉取，不切换分支，也不更新学习基线。

## 如何处理结果

| 发现 | 教学处理 |
|---|---|
| 相关范围无变化 | 在原基线上继续，仍以当前课对应源码为依据 |
| 文档或实现有变化 | 先对照对应主题，再修订受影响课程；变化不一定等于不兼容 |
| 接口、工具 schema、事件或配置语义变化 | 重读消费者与调用点，更新插件并运行针对性验证 |
| Session 类型或格式变化 | 先查 session-format-status 和持久化类型变更指南；产品版本不等于 Session 格式版本 |
| 当前分支与基线分叉 | 比较两个提交的内容，不能称为“升级了几个提交” |
| 基线提交不存在 | 明确历史不足；关键文件哈希仍可提供有限证据，不能假称完成历史比较 |
| 工作区有未提交修改 | 区分本地修改与上游变化；课程注明采用哪一份，不能只记录 HEAD |

“没有发现相关变化”只是所跟踪范围内的结果，不是所有插件都兼容的保证。新增课程引用更多文件时，把它们加入跟踪范围。

## 保留旧课，建立新依据

先解释变化影响，再修订课程与 SOURCE_BASELINE.json。不要只改 JSON 中的提交号消除提示。重要改动记录“旧行为 → 新行为 → 影响哪项实践”；用户先前的正确答案若因版本变化失效，要指出版本差异。

稳定学习目标是职责关系：谁管理生命周期、谁调用模型、谁执行工具、上下文从何而来。函数名、文件位置、配置字段和事件负载是需要随版本核对的具体实现。即使架构原则也应接受新源码的检验。

## 上游与本地是两种检查

源码目录更新后，本脚本即可发现本地差异；它不能判断网络上的最新提交。若用户想核对上游，另行查询官方仓库的版本与提交，再决定采用哪个版本。用户目前没有要求定时监控。

官方 README 明确说明项目处于开发预览阶段，可能有不兼容变化：[官方仓库](https://github.com/deepseek-ai/deepseek-harness)。基线内对应约束见根 AGENTS.md 的 Pre-stable APIs。
