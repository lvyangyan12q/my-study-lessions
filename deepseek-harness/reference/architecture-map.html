六个常用词

Plugin · 插件
Cordis 加载、激活、卸载的单元。可以注册工具、提供服务、监听事件；并非每个插件都是工具，也并非必须继承 Service 类。
Context / ctx · 上下文
访问插件服务和事件的入口。插件通过 ctx.tools、ctx.llm 等键使用能力；这里不是专指模型的上下文窗口。
Tool · 工具
对模型暴露名称、说明和输入 schema 的可调用能力。执行后，规范值经渲染成为模型可见结果。
Session · 会话
追加事件形成的会话记录；模型历史从它派生。不是所有日志事件都会成为模型消息。
Turn · 轮次
一次处理工作的范围，从 turn/start 到 turn/end。可以包含零个或多个 step。
Step · 步
围绕模型请求及相关工具调用的处理单元。正常路径一次请求；重试可能有多次尝试。

依据：Architecture；插件的三种形式；step 实现。

四个插件开发关键词

关键词记住的关系
apply(ctx)插件激活时安装能力的入口。
inject声明服务依赖。必需依赖齐备才能激活；依赖消失也影响消费者生命周期。
effect / disposer申请资源时绑定清理。ctx.on 与 ctx.tools.register 已管理相应清理；自建 timer 等用 ctx.effect 返回 disposer。
waterfall / next()可包装或短路的调用链。只观察或包装时调用 next()；不调用会截断后续处理。

依据：Cordis primer；服务依赖；工具 register 的 effect。

别混淆：插件的 inject 是服务依赖声明；agent.inject() 是注入下一次请求可用的上下文，单独调用它不会唤醒 idle agent。见 工具参考。

如何选择二次开发入口

需求先看
改变加载哪些功能profile / bundle / patch；patch 替换整份目标 config，不能默认深合并
新增模型可调用能力工具注册、输入输出定义、取消信号
换一种能力实现Service Definition / Provider / Consumer；三个角色不一定拆成三个包
请求或工具的策略、观测相关 agent/*、tools/* 事件，先确认 dispatch mode
把 agent 接入自己的应用SDK 和支持的 profile 启动路径
增加需要恢复的会话状态SessionEventMap、投影、格式与迁移约束

依据：Where new behavior goes；能力分层；扩展 cookbook。
