# `docs/security.md` 知识点（未考核）

> 2026-10-03 起，`docs/` 用户文档不再逐篇出课；这里直接给知识点与考点。源文件：`packages/coding-agent/docs/security.md`。

## 一、核心立场
- 把**模型生成的命令与代码当作不可信**。Pi 能以启动它的账户权限读/改/执行文件，且**不会在每次工具调用前征求同意**。
- 扩展、包安装器、LSP 等子进程**同样**是这些权限（除非有 OS / 虚拟化边界）。
- 文件、注释、指令、命令输出、模型回应都可能通过**提示注入**操纵模型。
- **项目信任只管「启动时加载哪些项目资源」，既不让内容变安全，也不是沙箱。**

## 二、三种运行方式的边界
| 怎么跑 | 保护住什么 |
|---|---|
| 直接用（OS 用户权限） | 该用户访问不到的东西；专用账户可收窄 |
| 整个跑在容器 / VM / 沙箱里 | 你没暴露进去的宿主文件与进程（**通常最稳**） |
| 主体在外，只有内置工具在隔离环境里 | 经这些工具的动作；Pi 本身与其它扩展仍在边界外（较窄） |

- 工作目录只控制资源发现与工具默认位置，**不阻止命令访问进程能访问的其它路径**。

## 三、项目信任（project trust）
- **需要信任决策的资源**：`.pi/settings.json`、`.pi/mcp.json`、`.pi/extensions|skills|prompts|themes`、`.pi/SYSTEM.md` / `APPEND_SYSTEM.md`、当前目录或祖先目录里的项目 `.agents/skills`。
- **裸 `.pi` 目录不需要**信任。
- 决策顺序：`--approve` / `--no-approve` → 扩展的 `project_trust` 事件 → 保存的决策（`~/.pi/agent/trust.json`，**取最近的父目录**）→ `defaultProjectTrust`（默认 `"ask"`）。
- 非交互模式（print / JSON / RPC）**弹不出信任提示**：`always` 才加载受保护资源，`ask`/`never` 跳过；自动化时用 `--approve` / `--no-approve`。
- **例外**：Pi 在选择/创建会话时**先读**项目 `sessionDir`（在解析信任之前），拒绝信任也撤不回这一次查找。
- **上下文文件**（`AGENTS.md`、`CLAUDE.md` 等）**不受信任控制**，始终加载——即使拒绝信任也要把其中的指令当不可信输入。

## 四、降低影响的做法
只给必要文件/服务；改动前用快照/备份/版本控制；加载前 review 扩展与包；用窄作用域、短时效凭据；应用结果前 review diff；导出/分享前 review 会话。
