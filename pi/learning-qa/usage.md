## 第一轮

### 问题 1：概念

Pi 正在工作时，你可以用三种方式介入。分别写出：**按键、生效时刻、对应的术语（steer / follow-up / abort）**。

#### 我的回答

调整当前任务 Enter；
追加后续工作 Alt+Enter；
把排队消息收回编辑器 Alt+Up；
停止当前任务 Escape；
用 Enter 发的消息会等当前回应及其工具调用结束，然后引导下一次回应。用 Alt+Enter 发的 follow-up 会等 Pi 完成当前任务。中止（abort）会把排队消息退回编辑器。
#### 批改

**基本正确，但漏了「术语」。** 你列了 Enter / Alt+Enter / Escape 的行为和生效时刻，与原文一致。但题目还要求对应术语：**Enter = steer（引导/转向）**、**Alt+Enter = follow-up（后续）**、**Escape = abort（中止）**。另外你多列的 <kbd>Alt+Up</kbd> 是「把排队消息收回编辑器」，不属于这三种介入，是补充操作。

### 问题 2：执行流程（场景判断）

场景：Pi 正在跑一个多步任务，已经连续做了 3 次工具调用。你在第 2 步时发现方向不对，希望**它在当前这一轮工具调用一结束就改道**，而不是等整个任务做完。

(a) 你该按哪个键？为什么**不能**用另一个「发消息」的键？
(b) 如果你改主意、直接按 <kbd>Escape</kbd> 中止，那些你之前排队但还没送达的消息去哪了？

#### 我的回答

调整当前任务 Enter；
另一个是等任务完成才触发
继续发送
#### 批改

- **(a) 对。** 按 <kbd>Enter</kbd>（steer）：它等当前回应 + 工具调用结束就送达；<kbd>Alt+Enter</kbd>（follow-up）要等整个任务结束——所以「本轮结束就改道」只能用 Enter。
- **(b) 错。** 你答「继续发送」，不对：abort 会把**排队消息退回编辑器**（不会自动发出去），之后你可以改了再发。

#### 批改
