# 阶段 2 起点：agent 最小循环收口（lessons/0003）

2026-10-18，主线提速后的第一阶段 2 第 1 课。用户读完 `lessons/0003-agent-loop.html`（概念课：agent = while 循环 + messages 数组 + 模型调用 + 工具执行）后按考核流程出题：第一轮 3 题（概念 / 执行流程 / 最小修改），有 2 题存薄弱点，追加 2 道强化题，判对后收口。

## 确认掌握的

- **三样东西 + 模型无状态**：能给出完整因果链（无状态 → 每轮重发整个数组 → 数组只增不减 → 撑爆窗口 → 需要压缩）。这是后面所有扩展知识的地基，也是「手搓 agent」的起点。
- **7 行四动作及顺序**：调模型 → 模型消息入栈 → 判断有无 toolCall → 执行工具并把结果入栈。
- **唯一正常出口**：`calls.length === 0`；其余退出（error / aborted / length）都不算任务完成。
- **工具结果必须回灌**：独立 `toolResult` 消息；参数校验属「执行工具」这一步的内部动作。
- **落层分界**：能正确区分「循环体必要动作」与「入口/出口工程复杂度」（排队消息、中断、故障保护）——强化题三问全判对。

## 被纠正 / 待复测的

- **「数组会不会变短」**：用户答「一般不会，压缩会变短」——方向对（点出压缩是易混点），但结论要修：**压缩也不改 messages 数组**，它改的是「下一次发给模型的上下文」（全量 → 摘要 + 从 `firstKeptEntryId` 起的保留段）；会话原始条目一条不删。这属阶段 7 主题，先记录、列入**间隔复测**，不在此处加练。
- **工具结果角色的「本质理由」**：用户能说出「分开模型才知道是工具结果」，但没点到**生成者不同**（assistant 是模型说的，toolResult 是 pi 产的）。已补讲。
- **答题习惯**：强化题 (a) 只给结论、未写理由。延续既有观察——推理/判断类题目必须显式要求并检查「判断过程」。
