把 package.json 当作边界契约

二次开发的第一步不是读所有代码，而是确认外部能够执行什么、导入什么，以及构建后必须带走什么。

一个文件，三个边界

边界关键字段你要回答的问题
命令行bin终端中的 pi 最终执行哪个文件？
库 APImain、types、exports调用者被允许从哪些路径导入哪些产物？
发布产物files、scripts构建和发布后，运行所需的非代码资源是否仍然存在？
二次开发判断：能由公开 exports 完成的集成，不要先改内核；能由 Extension 完成的行为，不要先 fork。

动手

  1. 打开 package.json，分别找到三个边界的配置。
  2. 从 build:binary 沿命令链追到 copy-binary-assets。
  3. 解释为什么可执行文件旁还需要主题、文档、示例和图像处理 WASM。
  4. 关闭本页，凭记忆完成 第一轮问题。

检索练习（合上再答）

不看上面，说出 package.json 的三个边界和各自的关键字段。

命令行边界：bin；库 API 边界：exports / main / types；发布产物边界：files / scripts。

exports 里写的是哪种路径？

  • 包内相对
  • 外部包名
  • 绝对路径
  • 网络地址

完成标准

你能在不查看文件时解释四个入口字段，并写出新增一个公开子路径所需的最小 exports 修改。
