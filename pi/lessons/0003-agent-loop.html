Agent 就是一个 while 循环

7 行伪代码，加上它在真实源码里的样子。

这节课结束时你能做到

不看任何资料，写出最小 agent 循环的 7 行；并在 packages/agent/src/agent-loop.ts 里逐个指出那 7 行分别落在哪。

一、agent 只有三样东西

把 "agent" 这个词拆掉之后，剩下的东西少得让人失望：

  1. 一个 messages 数组。这是模型唯一能看到的世界。
  2. 一次模型调用。流式返回文字，或者返回"我要调用某个工具"。
  3. 一次工具执行。跑完，把结果写成消息塞回数组。
关键事实

模型是无状态的。它不记得上一次调用。所谓"上下文""记忆"，就是你每次把整个数组再发一遍。

这也解释了为什么会有上下文压缩（compaction）：数组只会变长，总有一天撑爆窗口。

依据：packages/agent/README.md 的 "Message Flow" 一节；词汇表里的 compaction。

二、7 行

去掉重试、中断、排队消息、事件通知，循环本体就是这些：

while (true) {
  const msg = await callModel(messages)      // 把整个数组发出去
  messages.push(msg)                         // 模型说的话先入栈
  const calls = msg.content.filter(isToolCall)// 它要求用工具了吗
  if (calls.length === 0) return             // 没有 -> 唯一正常的出口
  for (const call of calls) messages.push(await runTool(call))
}                                            // 结果入栈，再转一圈

下面把它逐帧播放一遍。注意右侧 messages 数组怎么长——那是整个 agent 的全部状态。

三、真实源码里的样子

上面那 7 行，在 pi 里对应 runLoop() 的内层循环。骨架几乎一样：

while (hasMoreToolCalls || pendingMessages.length > 0) {
  const message = await streamAssistantResponse(...);
  if (message.stopReason === "error" || message.stopReason === "aborted") { ... return; }

  const toolCalls = message.content.filter((c) => c.type === "toolCall");
  hasMoreToolCalls = false;
  if (toolCalls.length > 0) {
    ...
    hasMoreToolCalls = !executedToolBatch.terminate;
  }
}

摘自 packages/agent/src/agent-loop.ts，runLoop()。为了读起来清楚，省略了 emit 与错误处理。

差别只有三处，都是"不信任环境"换来的：

  1. 用标志位代替 return。因为循环条件里还有 pendingMessages——用户在你思考的时候又打了字，那些话要插进来。
  2. 多包一层外层循环，专门处理"agent 本来要停了，但队列里又来了消息"。
  3. 提前退出与截断保护。error / aborted 直接结束；stopReason === "length" 说明输出被 token 上限截断，此时所有工具调用的参数都可能被切半，于是整批判为失败，让模型重新发起。
记住这个形状

生产级 agent 的复杂度几乎全部堆在循环的入口和出口（排队消息、中断、故障、压缩）。循环体本身，永远是那 7 行。

四、检验

先别看上面的代码。凭记忆回答。

1. 最小 agent 循环有哪四个必要动作？（顺序也要）

调模型 → 把模型消息入栈 → 判断有没有 toolCall → 执行工具并把结果入栈。第四步之后回到第一步。

容易漏的是第二步：很多人先判断再入栈，结果工具调用凭空消失。

2. 工具执行完，为什么必须把结果写回 messages？不写回会怎样？

因为模型无状态，它只能读到 messages 数组。工具执行的副作用（文件内容、命令输出）对模型完全不可见。

不写回的结果是：下一轮模型收不到任何反馈，只能重复同一个工具调用，或者干脆开始编。

3. 下面哪一步最应该在"执行工具"之前做？

  • 校验参数
  • 调用模型
  • 追加结果
  • 记录耗时

4. 模型的 stopReason 是 length 时，pi 怎么处理这条消息里的工具调用？

  • 逐个执行
  • 直接忽略
  • 全部失败
  • 截断重试
