docs/ 地图：需求 → 文档

官方 docs/index.md 只回答一个问题：我想做 X，该读哪一篇。它不教你用 Pi，它是一张索引。学会看它，后面几十篇文档你就不用通读，按需取。

这一课带走什么

离开时你能：① 说出文档分成哪几组；② 拿到一个需求，三秒内指出该翻哪一篇。

一张图看懂文档地图

需求路由：点一个需求，看该翻哪篇

这是这张地图唯一的用法。先有需求，再找文档——不要从 A 读到 Z。点下面的需求按钮，目标文档会高亮。

地图只是一层

index.md 只列一级入口。docs/ 下还有近 40 篇更细的文件（如 compaction.md、session-format.md、mcp.md、rpc-commands.md），它们从一级篇目里链接出来，按需进入即可，不在这张图上。

主要出处

读原文：docs/index.md（一屏，5 分钟）。对照上一课 README：四种模式与定制阶梯——index.md 的「Automate or embed」正是那四种模式的文档入口。

检索练习（合上再答）

不看上面，说出 docs/index.md 把文档分成的五组（中文即可）。

① 开始用 Pi（Start using Pi）② 定制 Pi（Customize Pi）③ 自动化或嵌入（Automate or embed）④ 查阅与平台设置（Reference and setup）⑤ 安全工作（Work safely）。

需求：在 CI 脚本里跑一次提示、拿最终结果就退出。先翻哪一篇？

  • 打印模式
  • 交互模式
  • 主题配色
  • 模型选择

需求：同事在 Windows 上按键不对。先翻哪一篇？

  • 平台设置
  • 安全边界
  • 会话分叉
  • 模型路由

哪里不清楚，直接问教师——尤其是「这个需求到底该读哪组」。别靠猜带到下一篇。
