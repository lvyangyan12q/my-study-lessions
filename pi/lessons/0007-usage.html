Lesson 0007 · 约 10 分钟 · 核心：三种介入方式

在终端里用 Pi：界面、介入、命令

这一篇是 Pi 交互模式的操作手册。它本身没什么深渊，但有一个点值得记住：Pi 干活时你可以用三种方式介入，而它们分别落在 agent 循环的不同时刻——这正是「系统提示 + 事件」之外，人能实时影响循环的三个入口。

这一课带走什么

看懂界面三块；记住三种介入方式（Enter / Alt+Enter / Escape）各自何时生效；常用斜杠命令和 ! 命令能随手用。

界面三块

区域显示什么
对话（transcript）你的提示、Pi 的回应、工具调用与结果、错误
编辑器（editor）写提示和命令的地方；边框颜色表示当前 thinking 级别
状态栏（footer）当前目录、会话、模型、上下文用量、累计用量与花费

启动头（startup header）列出 Pi 本次加载的指令和资源。Pi 不会在每次工具调用前都问你——所以要自己 review 命令与改动，不可信场景用沙箱（见 security.md）。

输入与引用

  • 输入后按 Enter 发送；Shift+Enter 换行；Ctrl+G 用外部编辑器写长提示。
  • @ 搜索文件并加入提示；Tab 补全路径；图片可直接粘贴或拖进支持的终端。

工作中：Ctrl+O 展开/折叠工具输出；Ctrl+T 显示/隐藏 thinking 块。

三种介入方式（重点）

Pi 正在干活时，你仍能发消息。区别在于消息在什么时刻生效：

你想操作送达时机
调整当前任务Enter当前回应及其工具调用结束后——引导下一次回应（steer）
追加后续工作Alt+EnterPi 完成当前任务后（follow-up）
把排队消息收回编辑器Alt+Up—
停止当前任务Escape立即；排队消息回到编辑器

这套「steer / follow-up / abort」的语义，与 how-pi-works.md 里 agent 循环的描述一一对应——阶段 2 会回到它。Windows Terminal 保留了部分 Alt 快捷键，替代方案见 terminal-setup.md。

常用命令（输入 / 搜索）

命令作用
/model选模型（Ctrl+L 同效）
/thinking设置推理投入级别（Shift+Tab 循环）
/login · /logout管理 provider 访问
/settings改常用偏好
/new · /resume · /name · /session新会话 / 打开旧会话 / 命名 / 查看会话信息
/tree · /fork · /clone · /compact探索分支而不丢工作 / 压缩发给模型的历史
/copy · /export · /share复制上一条回应 / 导出 HTML 或 JSONL / 上传拿查看链接
/hotkeys · /debug查看当前快捷键 / 写诊断日志 pi-debug.log

Prompt template、Skill、Extension 都能往这个 / 菜单里加命令——这就是后面的定制线。

跑命令、分享、诊断（要点）

  • 命令前加 !：执行并把输出带进对话（!git status）；!! 只执行、输出不给模型。
  • /share 会把会话上传并生成查看链接（Radius 组织内可见，否则经 GitHub CLI 建私有 gist）——分享前先自查，会话里可能有提示、工具输出、文件内容甚至凭据。
  • 全屏（默认）固定编辑器与状态区；普通模式用终端自身回滚。/settings 或 --tui-mode 切换。
  • /debug 把渲染行和当前会话消息写到 agent 目录下的 pi-debug.log；分享前也先自查。

检索练习（合上再答）

不看上面，说出 Pi 工作中三种介入方式：按键、何时生效、术语。

Enter = steer（等当前回应 + 其工具调用结束再送达）；Alt+Enter = follow-up（等整个任务结束才取）；Escape = abort（立即停止，排队消息退回编辑器）。

按 Enter 发的引导消息，什么时候送达？

  • 本轮结束后
  • 整个任务后
  • 立即就中止
  • 收回编辑区

按 Escape 中止后，排队但未送达的消息会怎样？

  • 收回编辑区
  • 立即发出去
  • 自动丢弃掉
  • 排到下一轮
