Choose a Model：连接方式与模型配置

内置 provider 用 /login + /model 就够了；这篇真正要带走的是一个判断：手里有什么，就选哪种连接方式——只有 Pi 不认识你的 endpoint 时，才去写 models.json。

这一课带走什么

能按「你手里有什么」选对连接方式；能给一个兼容端点写出最小 models.json；知道分类/图像模型为什么不出现在 /model 里。

核心：先选连接方式

选模型、选思考级别

  • /model：搜索可用模型（只显示认证可用的）；在某模型上按 Ctrl+S 存为新会话默认。
  • /thinking：选当前模型的思考级别，按 Ctrl+S 存为启动级别；选项受该模型支持范围限制。
  • Ctrl+P 循环切换可用模型；用 /scoped-models 控制这个循环。
  • 会话会记录模型与思考级别的变更；恢复会话会恢复它们，但不改新会话的默认值。

兼容端点：最小 models.json

当端点说的是 Pi 已支持的 API（Ollama、LM Studio、vLLM、SGLang、多数代理），就用这个：

{
  "providers": {
    "ollama": {
      "baseUrl": "http://localhost:11434/v1",
      "api": "openai-completions",
      "apiKey": "ollama",
      "models": [ { "id": "qwen2.5-coder:7b" } ]
    }
  }
}
  • 那个 "ollama" 是占位 key：只为让模型在 Pi 里可见，Ollama 不看它。
  • 需要认证时，apiKey / header 值可以写 $NAME / ${NAME} 环境插值、字面值，或以 ! 开头的命令；models.json 里的命令在请求时执行、不被缓存（对比：auth.json 的命令会缓存）。
  • 打开 /model 会重新加载该文件；models 条目增/替同 ID 模型；modelOverrides 只改元数据、不替换整个模型列表，未知 ID 被忽略。

分类 / 图像模型（不在 /model 里）

有意思的连接：我前面给你打分用的 jev，就是这里的分类模型（classifier）——它不聊天，只对 JSON 状态回答选择题 / 是非题 / 打分题，并给出概率。

分类模型和图像模型都不出现在 /model 里，而是通过 codemode 工具访问；脚本里用 models.getModelOfType("classifier", ...) / models.classify(...)。要开 codemode："defaultTools": ["+codemode"]。扩展则用 ctx.modelRegistry.classify()，无需 codemode。

两个补充

  • 缓存寿命：模型可用 promptCache: { "short": 300, "long": 3600 } 声明提供商的最优缓存寿命；没有对应寿命的模型不参与 cache warming。取官方区间的保守端。
  • 认证顺序：多来源都在时，--api-key → auth.json → models.json 的 apiKey → 环境变量 / 云端凭据（第 8 课细讲）。

主要出处

docs/models.md。中英对照见 models 中英对照。
