Settings：覆盖关系与 defaultTools

设置这一篇字段很多，但真正要带走的是一个判断：项目设置覆盖用户设置，可资源列表是合并。搞清这一点，配置冲突就能自己定位。

这一课带走什么

说清两层设置的覆盖与合并；写对 defaultTools 的 +/− 语法；说出 compaction 三级回退顺序。

核心：覆盖 vs 合并

defaultTools 的语法

写法语义
["read","bash"]（纯名）替换默认选择
["+codemode"]在继承的选择上加工具
["-bash","+powershell"]减一个、加一个
[]（空数组）禁用所有内置工具（不禁扩展 / SDK 工具）

项目设置叠在用户设置之上：项目列表**只含 +/−** 时改用户选择；**含纯名**时替换。改完 /reload 只**启用新增**的工具，不关闭被移除的、也不重新启用你手动关掉的。

compaction 三级回退

只有少数项**只能在 agent 目录设置**：defaultProjectTrust、httpProxy；cacheWarming 只能全局。

检索练习（合上再答）

项目设置和用户设置，谁覆盖谁？资源列表呢？

项目设置覆盖用户设置；但资源列表是合并（两处的资源都会加载）。

defaultTools 写 ["+codemode"] 的效果是？

  • 新增工具
  • 替换工具
  • 禁用工具
  • 清空工具

下面哪一项只能在 agent 目录设置？

  • 项目信任
  • 普通设置
  • 资源列表
  • 主题配色
