Security：信任不等于沙箱

这一篇只有一句话最要命：项目信任 ≠ 沙箱。它只决定「启动时加载哪些项目资源」，管不了工具之后能碰什么。真正的安全来自隔离。

这一课带走什么

说清项目信任管什么、不管什么；说出信任决策的优先级；知道三种运行方式各自的边界。

核心：信任决策的顺序

项目信任：管什么 / 不管什么

管：是否加载**受保护的项目资源**——.pi/settings.json、.pi/mcp.json、.pi/extensions|skills|prompts|themes、.pi/SYSTEM.md/APPEND_SYSTEM.md、项目 .agents/skills。裸 .pi 目录**不需要**信任。
不管：工具调用能访问/影响什么。启动后，已启用的工具仍以 Pi 进程的 OS 权限运行。

三种运行方式，各自保护什么

怎么跑保护住什么
直接用（OS 用户权限）该用户访问不到的东西；专用账户可收窄
整个跑在容器 / VM / 沙箱里你没暴露进去的宿主文件与进程（通常最稳）
主体在外、只有内置工具在隔离环境里经这些工具的动作；Pi 与其它扩展仍在边界外（较窄）

工作目录只控制资源发现与工具默认位置，**不阻止命令访问进程能访问的其它路径**。非交互模式（print / JSON / RPC）弹不出信任提示：只有 always 才加载受保护资源。

检索练习（合上再答）

项目信任是沙箱吗？它到底管什么、不管什么？

不是沙箱。它只管「启动时加载哪些受保护的项目资源」；不管工具调用之后能访问/影响什么——那些仍以 Pi 进程的 OS 权限运行。

项目信任属于什么？

  • 不是沙箱
  • 就是沙箱
  • 只在网络
  • 只在离线

信任决策的第一优先级是？

  • 命令开关
  • 扩展事件
  • 保存决策
  • 全局默认
