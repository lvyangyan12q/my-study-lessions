Stateful agent / 有状态 agent

Stateful agent with tool execution and event streaming. Built on @earendil-works/pi-ai.
带工具执行与事件流的有状态 agent，构建在 @earendil-works/pi-ai 之上。
npm install @earendil-works/pi-agent-core

Core Concepts / 核心概念

The agent works with AgentMessage, a flexible type that can include:
agent 用 AgentMessage，这是一个灵活的类型，可包含：
Standard LLM messages (user, assistant, toolResult)
标准 LLM 消息（user、assistant、toolResult）
Custom app-specific message types via declaration merging
通过声明合并（declaration merging）加入应用自定义消息类型
LLMs only understand user, assistant, and toolResult. The convertToLlm function bridges this gap by filtering and transforming messages before each LLM call.
LLM 只懂 user、assistant、toolResult。convertToLlm 在每次 LLM 调用前过滤并转换消息，填补这一差距。

Message Flow / 消息流

AgentMessage[] → transformContext() → AgentMessage[] → convertToLlm() → Message[] → LLM
                    (optional)                           (required)
transformContext: Prune old messages, inject external context
transformContext：修剪旧消息、注入外部上下文（可选）
convertToLlm: Filter out UI-only messages, convert custom types to LLM format
convertToLlm：过滤掉 UI 专用消息、把自定义类型转成 LLM 格式（必需）

Event Flow / 事件流

The agent emits events for UI updates. Understanding the event sequence helps build responsive interfaces.
agent 发出事件供 UI 更新；理解事件顺序有助于构建响应式界面。
prompt("Hello")
├─ agent_start
├─ turn_start
├─ message_start   { message: userMessage }
├─ message_end     { message: userMessage }
├─ message_start   { message: assistantMessage }
├─ message_update  { message: partial... }
├─ message_end     { message: assistantMessage }
├─ turn_end        { message, toolResults: [] }
└─ agent_end       { messages: [...] }
If the assistant calls tools, the loop continues: after the assistant message_end come tool_execution_start/update/end, the toolResult message, turn_end, then a new turn_start for the next LLM request, until no tool calls remain.
若 assistant 调用工具，循环会继续：assistant 的 message_end 之后是 tool_execution_start/update/end、toolResult 消息、turn_end，然后为下一次 LLM 请求开一个新的 turn_start，直到没有工具调用。
Tool execution mode is configurable. parallel (default): preflight tool calls sequentially, execute allowed tools concurrently, emit tool_execution_end as soon as each tool is finalized, then emit toolResult messages and turn_end.toolResults in assistant source order. sequential: execute tool calls one by one.
工具执行模式可配置。parallel（默认）：顺序预检，并发执行，每个工具定稿就发 tool_execution_end，但 toolResult 消息与 turn_end.toolResults 仍按 assistant 源码顺序。sequential：逐个执行。
If any tool call in a batch targets a tool with executionMode: "sequential", the entire batch executes sequentially regardless of the global setting.
批里只要有一个调用命中 executionMode: "sequential" 的工具，整批都顺序执行，无视全局设置。

Event Types / 事件类型

Event说明
agent_start / agent_end运行开始 / 结束（agent_end 是最后一个事件）
turn_start / turn_end一轮开始 / 结束（一次 LLM 调用 + 工具执行）
message_start / message_end任意消息开始 / 结束
message_update仅 assistant：带 assistantMessageEvent 增量
tool_execution_start / _update / _end工具开始 / 流式进度 / 结束

Agent Options / Agent 选项（要点）

convertToLlm converts AgentMessage[] to LLM Message[] (required for custom message types).
convertToLlm：把 AgentMessage[] 转成 LLM 的 Message[]（自定义消息类型必需）。
transformContext transforms context before convertToLlm (for pruning, compaction). streamFn is required and receives a TranscriptContext.
transformContext：在 convertToLlm 之前转换上下文（用于修剪、压缩）。streamFn 必需，接收 TranscriptContext。
beforeToolCall runs after args are validated and can block execution. afterToolCall postprocesses each result before final tool events are emitted.
beforeToolCall 在参数校验后、执行前运行，可拦截；afterToolCall 在执行后、发最终工具事件前处理每个结果。
prepareRequest rebuilds finalized context immediately before every provider request. finishTurn finalizes a completed turn before turn_end (continue ensures one next request; end ends the run).
prepareRequest 在每次 provider 请求前重建最终上下文；finishTurn 在 turn_end 前收尾（continue 保证再来一次请求；end 结束运行）。

Agent State / Agent 状态

Access state via agent.state. Assigning agent.state.tools = [...] or agent.state.messages = [...] copies the top-level array before storing it.
用 agent.state 访问状态。给 agent.state.tools / agent.state.messages 赋值时会先复制顶层数组再存储。
The transcript owns the system prompt and tool declarations. agent.state.systemPrompt is read-only; agent.state.tools is the executable loadout, diffed against declared tools before every request.
transcript 拥有 system prompt 与工具声明。agent.state.systemPrompt 只读；agent.state.tools 是可执行装载，每次请求前都会与声明的工具做差集比对。
During streaming, agent.state.streamingMessage contains the current partial assistant message. isStreaming stays true until the run fully settles, including awaited agent_end subscribers.
流式过程中，agent.state.streamingMessage 是当前的部分 assistant 消息；isStreaming 到运行完全落定（含 await 的 agent_end 订阅者）才变 false。

Steering and Follow-up / 引导与后续

Steering messages let you interrupt the agent while tools are running. Follow-up messages let you queue work after the agent would otherwise stop.
steering 消息让你在工具运行时介入；follow-up 消息让你在 agent 本会停止后排入后续工作。（这就是第 7 课那三个介入方式在 API 层的形态。）
When steering messages are detected after a turn completes: all tool calls from the current assistant message have already finished; steering messages are injected; the LLM responds on the next turn.
一轮完成后检测到 steering：当前 assistant 的全部工具调用已完成 → 注入 steering → 下一次回应在下一轮产生。
Follow-up messages are checked only when there are no more tool calls and no steering messages. If any are queued, they are injected and another turn runs.
只有在没有更多工具调用、也没有 steering 时，才检查 follow-up；若有排队，就注入并再跑一轮。

Tools / 工具

Define tools using AgentTool. Set executionMode to override the global execution mode for that tool.
用 AgentTool 定义工具；executionMode 可覆盖该工具的执行模式。
Throw an error when a tool fails. Do not return error messages as content. Thrown errors are caught by the agent and reported to the LLM as tool errors with isError: true.
工具失败时抛错，不要把错误信息当内容返回。抛出的错误会被 agent 捕获，作为 isError: true 的工具错误报告给 LLM。
Return terminate: true from execute(), a blocked beforeToolCall, or afterToolCall to hint that the agent should stop after the current batch. Takes effect only when every finalized result in the batch is terminating.
从 execute()、被拦截的 beforeToolCall、或 afterToolCall 返回 terminate: true，提示在本批后停止。只有当批里每个定稿结果都 terminate 才生效。

Low-Level API / 底层 API

For direct control without the Agent class, use agentLoop() and agentLoopContinue().
不用 Agent 类、直接控制时，用 agentLoop() 与 agentLoopContinue()。
These low-level streams are observational. They preserve event order, but do not wait for your async event handling to settle before later producer phases continue. If you need message processing to act as a barrier before tool preflight, use the Agent class.
这些底层流是「观察式」的：保持事件顺序，但不会等你异步事件处理落定再继续后续生产阶段。若需要「消息处理在工具预检前形成屏障」，用 Agent 类。
