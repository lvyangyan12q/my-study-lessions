A · 安装与首次运行

  • 三种安装（各自怎么更新是差别关键）：脚本 curl -fsSL https://pi.dev/install.sh \| sh（macOS/Linux，锁定全部依赖，用 pi update 更新）；npm npm install -g --ignore-scripts @earendil-works/pi-coding-agent（需 Node 22.19+，不锁传递依赖）；Nix nix profile add github:earendil-works/pi/stable（从源码构建，pi update 管不了，用 nix profile upgrade pi）。
  • 首次流程：cd <工作目录> → pi → /login 选 provider 并认证 → 直接给任务。
  • 工作目录的两个作用：帮助 Pi 发现相关文件 / 指令 / 配置；给保存的会话分组。pi --continue 恢复的是「同一工作目录下最近一次会话」——靠工作目录，不是靠 session id。
  • 编辑器里输入 @ 可搜索并插入文件路径。
  • 定制选型器（决策变量 = 触发机制）：仓库常驻规则 → AGENTS.md；用户手动展开固定提示词 → Prompt template（/name）；模型按需加载的能力包 → Skill；事件驱动的代码 → Extension。能用轻的不用重的。

来源：docs/quickstart.md · 深读 课 0006 · 中英对照 · 问答

B · 运行模式与定制阶梯

定位：minimal, extensible agent harness——极简、可扩展，用 Extension / Skill / Prompt Template / Theme 扩展，不必 fork 内核。默认给模型四个工具 read、bash、edit、write。

模式入口适合谁
interactivepi人在终端里边聊边干活
printpi -p "..."（可读 stdin）脚本 / CI，一次性输出
JSONpi --mode json程序消费一次性 JSON 事件流
RPCpi --mode rpc跨进程、非 Node.js 集成（LF 分帧 JSONL）
SDKimport { createAgentSession } from "@earendil-works/pi-coding-agent"把 Pi 嵌进自己的 TS / Node 应用

定制阶梯（轻 → 重）：Prompt Template → Skill → Extension → Theme → Pi Package。落层先问「谁触发、何时触发」。

E · 模型与 Provider

  • 凭据解析四级（高 → 低，第一个命中胜出）：① 运行时 --api-key → ② auth.json 已存凭据 → ③ models.json 的 apiKey → ④ provider 环境变量 / 云端 ambient。所以「设了环境变量它却不用」通常是因为已存凭据优先。
  • 五种连接方式：受支持订阅 → /login；API key → /login 或设环境变量；本地 GGUF → 接 llama.cpp router；OpenAI/Anthropic/Google 兼容端点 → 写 models.json；自定义协议 → 写/装 provider 扩展。
  • !command 密钥的差别：在 auth.json 里缓存到进程结束（空输出 / 超时 / 非零退出 → 保持未解析直到重启）；在 models.json 里请求时执行、不缓存。
  • 分类 / 图像模型不进 /model，经 codemode 工具访问（设置 "defaultTools": ["+codemode"] 打开）；扩展可直接用 ctx.modelRegistry.classify()。
  • /logout 移除 auth.json 里该 provider 的已存凭据（含 !command），但不取消环境变量、不改 models.json 的认证、也不在 provider 处吊销。

来源：docs/models.md · docs/providers.md · 深读 课 0009 · 课 0008 · 模型对照 · 凭据对照 · 问答

F · 配置与按键

  • 覆盖关系（最该记）：项目设置覆盖 agent 目录（用户）设置；但资源列表是合并，不是替换。少数项只能写在 agent 目录：defaultProjectTrust、httpProxy；cacheWarming 只能全局。
  • defaultTools 语法：纯名替换默认；+name 加、-name 减；空数组禁用所有内置工具。项目叠用户：只含 +/- 的列表改用户选择，含纯名的替换。/reload 只启用新增的工具，不关闭被移除的。
  • 内置扩展名：builtin:mcp、builtin:llama.cpp、builtin:codemode、builtin:tool-search（默认加载，可用 -builtin:mcp 关）。
  • 按键：文件 <agent-dir>/keybindings.json，格式「动作 id → 一个键或键数组」，值替换默认键，写 [] 可禁用；改完 /reload 生效，/hotkeys 查看。修饰键 ctrl/shift/alt/super 可叠；super 绑定需要终端支持 Kitty 键盘协议。
  • 常用默认键：Escape=interrupt、Ctrl+L=模型选择、Shift+Tab=思考级别、Ctrl+P=循环模型、Ctrl+O=工具输出折叠。

来源：docs/settings.md · docs/keybindings.md · 深读 课 0011 · 课 0012 · 设置问答 · 按键问答

G · 会话与压缩

  • 会话：一次对话 = 一个 session；只有活动分支提供下一次模型请求的历史。pi --continue（当前工作目录最近）/ pi --resume（选择器，交互里 /resume 同效）/ --no-session（临时，退出不可恢复）。
  • 三种分叉：/tree 在同一会话文件内移动；/fork 从更早的用户消息新建会话；/clone 把当前活动分支复制进新会话。
  • 存储：默认 ~/.pi/agent/sessions/，按工作目录分组。改位置优先级 --session-dir > PI_CODING_AGENT_SESSION_DIR > sessionDir 设置。
  • 两种摘要别混：Compaction（上下文超阈值或 /compact，把旧消息摘要掉腾上下文）vs Branch summarization（/tree 导航时，保留你离开那条分支的上下文）。
  • 触发阈值：contextTokens > contextWindow - reserveTokens；默认 reserveTokens = 16384、keepRecentTokens = 20000。
  • 切点规则（最该记）：可在 user / assistant / BashExecution / 自定义消息处切，绝不在 tool 结果处切（工具结果必须和它的工具调用待在一起）。原始条目全部保留，压缩只让它们不再发给模型；重复压缩从上一次的 firstKeptEntryId 起。这段是阶段 7 的地基。

来源：docs/sessions.md · docs/compaction.md · 深读 课 0013 · 课 0014 · 会话问答 · 压缩问答

H · 安全边界：信任 ≠ 沙箱

  • 核心立场：把模型生成的命令与代码当作不可信。Pi 以启动它的账户权限读 / 改 / 执行文件，且不会在每次工具调用前征求同意；扩展、包安装器、LSP 等子进程同样拥有这些权限。
  • 三种运行方式的边界：直接用（受 OS 用户权限限制）；整个跑在容器 / VM / 沙箱里（通常最稳）；主体在外、只有内置工具在隔离环境（较窄）。工作目录只影响资源发现与工具默认位置，不阻止命令访问进程能访问的其它路径。
  • 项目信任只管「启动时加载哪些项目资源」——既不让内容变安全，也不是沙箱。需信任决策的资源：.pi/settings.json、.pi/mcp.json、.pi/extensions|skills|prompts|themes、.pi/SYSTEM.md/APPEND_SYSTEM.md、项目 .agents/skills；裸 .pi 目录不需要。
  • 决策顺序：--approve/--no-approve → 扩展的 project_trust 事件 → 保存的决策（~/.pi/agent/trust.json，取最近父目录）→ defaultProjectTrust（默认 "ask"）。非交互模式（print / JSON / RPC）弹不出提示，只有 always 才加载受保护资源。
  • 上下文文件（AGENTS.md、CLAUDE.md 等）不受信任控制，始终加载——即使拒绝信任也要把其中的指令当不可信输入。

来源：docs/security.md · 深读 课 0015 · 问答
