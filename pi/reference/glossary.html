词汇表

课程里出现的术语，统一按这里的定义使用。新术语随课程追加。

读法：每条先给一句人话定义，再给一个"在代码里长什么样"的落点。定义与落点都来自 packages/agent/src/agent-loop.ts 与 packages/agent/README.md，不是我的记忆。

agent（智能体）
一个循环：把消息列表发给模型，执行模型要求的工具，把结果写回消息列表，直到模型不再要求工具。除此之外没有别的本体。 落点：runLoop()
agent loop（agent 循环）
上面那个循环本身。任务里的"手搓 agent"，手搓的就是它。 落点：runAgentLoop() / runLoop()
turn（轮）
一次"模型回复 + 执行它要求的全部工具"。一轮结束的标志是 turn_end 事件。 落点：emit({ type: "turn_end", ... })
toolCall（工具调用）
模型输出里的一个内容块，写着要调用哪个工具、参数是什么。它不是独立事件，只是 assistant 消息内容的一部分，所以要用 filter 从 message.content 里挑出来。 落点：message.content.filter((c) => c.type === "toolCall")
toolResult（工具结果）
一条独立的、role 为 toolResult 的消息，回灌进 messages。模型看不到工具的副作用，只能读这条消息，所以结果必须写成消息。 落点：createToolResultMessage()
stopReason（停止原因）
assistant 消息上的字段，说明模型为什么停下：正常结束、输出被 token 上限截断（length）、出错（error）、被中断（aborted）。循环用它决定继续还是退出。 落点：message.stopReason === "length"
streaming（流式）
模型不是一次性返回整条消息，而是逐块吐字、吐思考、吐工具调用。循环把中间态也 emit 出去，UI 才能边生成边显示。 落点：streamAssistantResponse() 里的 text_delta / toolcall_delta
compaction（上下文压缩）
messages 越来越长会撑爆上下文窗口，于是把早期的对话总结成一段摘要再替换掉。它存在的原因正是"模型无记忆，每轮都要重发全部消息"。 落点：packages/agent/src/harness/compaction/
AgentMessage vs LLM Message
两套消息类型。agent 内部用更宽的 AgentMessage（可以塞 UI 专用消息），发给模型前必须经 convertToLlm() 过滤成模型认识的 user / assistant / toolResult。 落点：config.convertToLlm(messages)
extension（扩展）
一个 TypeScript 模块，注册自定义工具/命令、订阅生命周期事件。它是"改 pi 行为"的正规入口，不必碰核心源码。 落点：packages/coding-agent/docs/extensions.md
isError（工具结果上的错误标记）
toolResult 消息上的布尔字段。错误结果与正常结果共用同一种消息类型，只靠这个标记区分。模型据此判断"拿到了内容"还是"出错了"。 落点：createToolResultMessage() 里的 isError: finalized.isError
validateToolArguments()
执行前用工具的 schema 校验模型给的参数。校验失败会抛错，循环把它接住、转成一条 isError 消息回灌，所以参数不合法不会中断 agent。 落点：prepareToolCall() 的 try 块
toolExecution（工具执行模式）
sequential 或 parallel。默认并行，但只要有任一被调用的工具声明为 sequential，整批都退化成顺序执行。 落点：executeToolCalls() 里的 hasSequentialToolCall
beforeToolCall / afterToolCall
官方给的两个插手点。before 可以 block（拦截调用，转成错误结果），after 可以改写结果的 content / isError / terminate。扩展想做权限门禁就走这里。 落点：prepareToolCall() 与 finalizeExecutedToolCall()
截断保护（truncated tool call）
stopReason 为 length 时，工具参数可能被 token 上限截半。这类调用能解析、能过校验，但语义残缺，所以整批不执行、全部报错，逼模型重新发起。 落点：failToolCallsFromTruncatedMessage()
