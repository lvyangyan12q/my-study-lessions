Choose a Model / 选择模型

For a built-in provider, start with /login, then choose a model with /model. Use custom model configuration only when Pi does not already include the provider or endpoint you need.
对内置 provider：先用 /login，再用 /model 选模型。只有当 Pi 没有你要的 provider / endpoint 时，才做自定义模型配置。

Choose a connection / 选择连接方式

What you have / 你手里有什么Recommended setup / 推荐做法
A supported subscription
受支持的订阅		Sign in through /login
A provider API key
provider 的 API key		Store it through /login or set its environment variable
A local GGUF model
本地 GGUF 模型		Connect Pi to the llama.cpp router
An OpenAI-, Anthropic-, or Google-compatible endpoint
兼容端点		Add it to models.json
A provider with a custom protocol or authentication flow
自定义协议 / 认证		Build or install a provider extension
Browse the model catalog for current providers, model IDs, capabilities, context limits, and pricing. Pi starts with its bundled catalog and can overlay newer catalog data from pi.dev. Cached catalog data remains available offline; run pi update --models to force a refresh.
在 模型目录 查看 provider、模型 ID、能力、上下文上限与价格。Pi 从内置目录启动，并能覆盖 pi.dev 的更新数据；缓存数据可离线使用，用 pi update --models 强制刷新。

Authenticate / 认证

Run /login and select a provider. Pi stores credentials in auth.json. Run /logout to remove stored credentials for a provider.
运行 /login 并选 provider，Pi 把凭据存进 auth.json；用 /logout 移除某 provider 已存凭据。
You can instead provide an API key through the provider's environment variable. This is useful in CI and other environments where Pi should not write credentials. Providers lists the variables and provider-specific setup.
也可以改用 provider 的环境变量提供 API key；这在 CI 等不该让 Pi 写凭据的环境有用。变量清单与 provider 专属设置见 Providers。
When several credential sources are configured, Pi uses a runtime --api-key first, then a stored auth.json credential, an apiKey from models.json, and finally the provider's environment variables or ambient cloud credentials. Provider extensions can define their own authentication behavior.
当配置了多个凭据来源时，Pi 先用运行时 --api-key，其次 auth.json 里存储的凭据，再是 models.json 里的 apiKey，最后是 provider 的环境变量或云端 ambient 凭据。Provider 扩展可定义自己的认证行为。
Keep auth.json and any credential commands private. Project settings and extensions can execute inside the Pi process after you trust a project. Review Security before loading configuration from an untrusted directory.
把 auth.json 和任何凭据命令保密。信任某个项目后，项目设置与扩展会在 Pi 进程内执行。从不可信目录加载配置前先读 Security。

Select a model / 选模型

Run /model to search available models. The picker shows models whose providers have usable authentication. Press Ctrl+S on a model to save it as the default for new sessions.
运行 /model 搜索可用模型；选择器只显示认证可用的模型。在某模型上按 Ctrl+S 存为新会话默认值。
Run /thinking to select the thinking level for the current model. Press Ctrl+S there to save the startup level. Pi limits the choices to levels supported by the selected model.
运行 /thinking 选当前模型的思考级别，按 Ctrl+S 存为启动级别；选项受所选模型支持范围限制。
Ctrl+P cycles through available models. Use /scoped-models to control that cycle and save the selection, or configure model patterns through Settings.
Ctrl+P 循环切换可用模型；用 /scoped-models 控制该循环并保存选择，或通过 Settings 配置模型模式。
A session records model and thinking-level changes. Resuming the session restores them without changing defaults for new sessions.
会话会记录模型与思考级别的变更；恢复会话会恢复它们，但不改新会话的默认值。

Connect local models / 连接本地模型

Pi integrates directly with the llama.cpp router. The router discovers GGUF files and loads models on demand. Pi's /llama command manages the router, while /model selects one of its loaded models.
Pi 直接集成 llama.cpp router：router 发现 GGUF 文件并按需加载模型。/llama 管理 router，/model 选它已加载的模型。
Follow Local Models with llama.cpp for server startup, model layout, downloads, and connection troubleshooting.
服务启动、模型布局、下载与连接排错见 Local Models with llama.cpp。
For Ollama, LM Studio, vLLM, SGLang, and other compatible servers, configure a compatible endpoint in models.json.
Ollama、LM Studio、vLLM、SGLang 等兼容服务器，在 models.json 里 配置兼容端点。

Configure a compatible endpoint / 配置兼容端点

Use models.json when an endpoint speaks an API Pi already supports. This includes most Ollama, LM Studio, vLLM, SGLang, and proxy deployments.
当端点说的是 Pi 已支持的 API 时，用 models.json；涵盖多数 Ollama、LM Studio、vLLM、SGLang 与代理部署。
{
  "providers": {
    "ollama": {
      "baseUrl": "http://localhost:11434/v1",
      "api": "openai-completions",
      "apiKey": "ollama",
      "models": [
        { "id": "qwen2.5-coder:7b" }
      ]
    }
  }
}
The dummy key makes the model available to Pi; Ollama ignores it. For an authenticated endpoint, apiKey and header values can use $NAME or ${NAME} environment interpolation, a literal value, or a leading !command. Commands in models.json run at request time and are not cached by Pi.
占位 key 只是让模型对 Pi 可见，Ollama 不看它。需要认证的端点，apiKey 与 header 值可用 $NAME / ${NAME} 环境插值、字面值，或以 !command 开头的命令；models.json 里的命令在请求时执行、不被缓存。
Opening /model reloads the file. A models entry adds or replaces a model with the same ID on that provider. Use modelOverrides to change metadata for an existing built-in or extension-provided model without replacing the provider's model list. Unknown override IDs are ignored.
打开 /model 会重新加载该文件。models 条目增/替同 ID 模型；用 modelOverrides 改内置或扩展提供模型的元数据、而不替换整个列表；未知 override ID 被忽略。

Describe model input and caching / 描述模型输入与缓存

Use inputLimits.images.resize to control how Pi encodes new image attachments, read results, and tool-result images before storing them in conversation history:
用 inputLimits.images.resize 控制 Pi 在把新的图片附件、read 结果、工具结果图片存入对话历史前如何编码：
{
  "id": "vision-model",
  "input": ["text", "image"],
  "inputLimits": {
    "images": {
      "resize": {
        "maxWidth": 1568,
        "maxHeight": 1568,
        "maxBytes": 524288,
        "jpegQuality": 75
      }
    }
  }
}
maxBytes limits the base64-encoded payload. Omitted resize fields use conservative defaults of 2000 by 2000 pixels, 4.5 MiB encoded, and JPEG quality 80. Images are encoded once; changing models does not rewrite historical images.
maxBytes 限制 base64 编码后的载荷。未写的 resize 字段用保守默认：2000×2000 像素、编码后 4.5 MiB、JPEG 质量 80。图片只编码一次；换模型不会重写历史图片。
Use promptCache to declare the provider's best-effort cache lifetime in seconds for the short or long retention tier:
用 promptCache 声明 provider 在 short / long 档的最优缓存寿命（秒）：
{ "id": "claude-sonnet-5", "promptCache": { "short": 300, "long": 3600 } }
Choose the conservative end of any published range. A model without a lifetime for the active tier is not eligible for cache warming. A modelOverrides entry can set inputLimits or promptCache for a built-in or extension model.
取官方区间的保守端。没有当前档寿命的模型不参与 cache warming。modelOverrides 可为内置或扩展模型设置 inputLimits 或 promptCache。
Compatibility settings should describe verified differences in the endpoint's request or response behavior. Do not enable them based only on an endpoint advertising OpenAI or Anthropic compatibility.
兼容性设置应描述端点请求/响应行为的**已验证**差异；不要仅凭端点自称 OpenAI / Anthropic 兼容就打开。

Use classifier models / 用分类模型

Classifier models do not chat. They answer typed questions about JSON state: pick one of several choices, answer yes or no, or give a score, each with probabilities.
分类模型不聊天。它们对 JSON 状态回答类型化问题：多选一、是非题，或打分题，每种都带概率。
ProviderModel IDsAuthentication
typesafejev-latestTYPESAFE_API_KEY
openroutertypesafe/jev-1.13, ~typesafe/jev-latestOPENROUTER_API_KEY or /login
cloudflare-workers-aitypesafe/jev, @cf/cloudflare/clef, @cf/cloudflare/clef-flashCLOUDFLARE_API_KEY + CLOUDFLARE_ACCOUNT_ID
vercel-ai-gatewaytypesafe-ai/jevAI_GATEWAY_API_KEY
opencodejev-1.13, jev-1.13-freeOPENCODE_API_KEY
Classifier models do not appear in /model. The model reaches them through the codemode tool, which is off unless an MCP server turned it on. Enable it with "defaultTools": ["+codemode"] in settings.
分类模型不出现在 /model 中；由模型通过 codemode 工具访问。该工具默认关闭（除非 MCP server 开启），用 settings 里的 "defaultTools": ["+codemode"] 启用。
const jev = await models.getModelOfType("classifier", "typesafe", "jev-latest");
const result = await models.classify(jev, {
  state: { message: "The change works, thanks." },
  questions: {
    approved: {
      type: "bool",
      instructions: "Does the user approve of the result?",
      criteria: { true: "Approval", false: "No approval" },
    },
  },
});
return result.answers;
When the service reports token counts, as all System One services do, result.usage carries them with their cost. Pi adds the usage of a script's classifier calls to the codemode tool result, so it counts toward the session cost.
当服务报告 token 数（所有 System One 服务都会），result.usage 会带上用量与花费。Pi 把脚本的分类调用用量计入 codemode 工具结果，从而计入会话花费。
Extensions call classifiers through ctx.modelRegistry.classify(), without codemode. Virtual models can use them to route requests.
扩展通过 ctx.modelRegistry.classify() 调用分类模型，不用 codemode。虚拟模型 可用它们做请求路由。

Use image models / 用图像模型

Image models generate images from a prompt and optional input images. Pi lists OpenRouter's image models under the openrouter provider; they use the same OPENROUTER_API_KEY or /login credential as its chat models.
图像模型从提示词（可带输入图）生成图片。Pi 把 OpenRouter 的图像模型列在 openrouter provider 下，复用与聊天模型相同的 OPENROUTER_API_KEY 或 /login 凭据。
Like classifier models, image models do not appear in /model; the model reaches them through the codemode tool.
与分类模型一样，图像模型不出现在 /model 中，由模型通过 codemode 访问。
Extensions generate images through ctx.modelRegistry.generateImages(), without codemode.
扩展通过 ctx.modelRegistry.generateImages() 生成图片，不用 codemode。

Add a custom provider / 加自定义 provider

Use an extension when the provider needs custom streaming, model discovery, or authentication behavior. See Custom Providers.
当 provider 需要自定义流式、模型发现或认证行为时，用扩展。见 Custom Providers。

Troubleshooting / 排错

A model does not appear: confirm that its provider has usable authentication. Custom models can load from models.json but remain unavailable in /model until Pi can resolve credentials.
模型不出现：确认其 provider 认证可用。自定义模型能从 models.json 载入，但在 Pi 解析出凭据前不会出现在 /model。
Authentication works in one shell only: check whether the key came from an environment variable rather than auth.json. Environment variables must be present in the process that starts Pi.
只在某个 shell 里认证有效：检查 key 是否来自环境变量而非 auth.json——环境变量必须存在于启动 Pi 的那个进程里。
A compatible endpoint rejects requests: check its API type and compatibility settings in models.json.
兼容端点拒绝请求：检查 models.json 里的 API 类型与兼容性设置。
