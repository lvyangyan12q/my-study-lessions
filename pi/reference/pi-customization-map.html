运行模式与定制阶梯

两个最高频的判断：用哪种方式运行 Pi；一个需求落在定制阶梯的哪一层。

四种运行模式

模式入口接口何时用
interactivepiTUI人机对话、日常开发
printpi -p "<prompt>"一次性文本脚本里拿一段回答
JSONpi --mode json一次性 JSON 事件流脚本要结构化事件
RPCpi --mode rpcstdin/stdout JSONL，仅按 \n 分帧跨进程、非 Node 客户端
SDKimport { createAgentSession } from "@earendil-works/pi-coding-agent"进程内 TS API嵌入自己的程序

README 口径：「四种模式」= interactive、print 或 JSON（合并计为一类）、RPC、SDK。

定制阶梯（从轻到重）

层形态触发目录
Prompt TemplateMarkdown/name~/.pi/agent/prompts/ · .pi/prompts/
SkillSKILL.md（Agent Skills 标准）/skill:name / 自动~/.pi/agent/skills/ · ~/.agents/skills/ · .pi/skills/ · .agents/skills/（cwd 向上）
ThemeJSON，热重载设置选用~/.pi/agent/themes/ · .pi/themes/
ExtensionTypeScript 模块启动自动加载~/.pi/agent/extensions/ · .pi/extensions/
Pi Package以上任意组合的包pi installnpm / git；装到 ~/.pi/agent/npm|git/，-l 装到项目 .pi/

选层口诀

提示词 → 说明 → 代码 → 打包分发 → 进程外调度 → 内核。能用轻的不用重的；能装包不自写；能扩展不 fork。

内建没有的（MCP、子代理、计划模式……）都用 Extension 补；Package 以完整系统权限运行，装前必读源码。
