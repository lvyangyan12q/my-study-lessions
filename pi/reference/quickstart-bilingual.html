Quickstart / 快速上手

Pi runs in your terminal and works with files on your machine. To use it, you need access to a model through a supported provider. This can be a subscription, an API key, or a local model.
Pi 在终端里运行，直接操作你机器上的文件。要用它，你需要通过一个受支持的 provider 访问某个模型——可以是订阅、API Key，或本地模型。
For native Windows setup, read Windows Setup. For Android, read Termux Setup.
Windows 原生安装见 Windows Setup；Android 见 Termux Setup。

1. Install Pi / 安装

On macOS or Linux, you can use the installer:
macOS 或 Linux 上可以用安装脚本：
curl -fsSL https://pi.dev/install.sh | sh
The installer pins all dependencies and updates Pi with pi update. Alternatively, install Pi from npm, which does not pin transitive dependencies. This requires Node.js 22.19 or newer:
安装脚本会锁定全部依赖，并用 pi update 更新 Pi。另一种方式是用 npm 安装，它不锁定传递依赖，要求 Node.js 22.19 或更新：
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
Pi does not require dependency lifecycle scripts for a normal npm installation.
正常用 npm 安装时，Pi 不需要依赖的生命周期脚本。
With Nix on macOS or Linux, install the latest release from Pi's flake. Nix builds Pi from source:
在 macOS 或 Linux 上用 Nix 时，从 Pi 的 flake 安装最新 release。Nix 会从源码构建 Pi：
nix profile add github:earendil-works/pi/stable
Older Nix versions use nix profile install instead. Update with nix profile upgrade pi; pi update cannot update a Nix installation. To pin a release, use a tag such as github:earendil-works/pi/v1.0.0.
较早的 Nix 版本改用 nix profile install。更新用 nix profile upgrade pi；pi update 无法更新 Nix 安装。要固定某个版本，可用形如 github:earendil-works/pi/v1.0.0 的 tag。
Verify the installation:
验证安装：
pi --version

2. Start Pi / 启动

Change to the folder you want Pi to work with, then start it:
切换到你想让 Pi 工作的文件夹，然后启动它：
cd /path/to/folder
pi
The working folder helps Pi discover relevant files, instructions, and configuration. Pi also uses it to group saved sessions.
工作目录帮助 Pi 发现相关文件、指令和配置；Pi 也用它给保存的会话分组。
The interface shows your conversation, an editor for prompts and commands, and a footer with the current folder, model, and session status. See Use Pi in the terminal to learn how to add files, run commands, direct ongoing work, and manage results.
界面显示：你的对话、输入提示词与命令的编辑器，以及底部状态栏（当前目录、模型、会话状态）。如何添加文件、运行命令、指挥进行中的工作、管理结果，见 Use Pi in the terminal。

3. Choose a model / 选模型

A model generates Pi's responses. A provider is the service or account Pi uses to access that model.
model（模型）负责生成 Pi 的回答；provider（提供方）是 Pi 用来访问该模型的服务或账号。
In Pi, run:
在 Pi 里运行：
/login
Choose a provider, then follow the prompts to use a subscription or store an API key. Run /model afterward if you want to select a different available model.
选一个 provider，然后按提示使用订阅或保存 API Key。之后想换一个可用模型，再运行 /model。
See Choose a model and provider for supported providers, environment-variable authentication, local models, and custom endpoints.
受支持的 provider、环境变量认证、本地模型与自定义端点，见 Choose a model and provider。

4. Give Pi a task / 给任务

Pi shows each file read, search, command, and edit it performs. It does not ask before every tool call.
Pi 会显示它执行的每一次文件读取、搜索、命令和编辑；但它不会在每次工具调用前都征求同意。
Enter a task that matches your work, for example:
输入一个贴合你工作的任务，例如：
Summarize @meeting-notes.md and save the action items to action-items.md.
Explain how this repository is structured and how to run its checks.
Compare @previous.csv with @current.csv and summarize the important changes.
Type @ in the editor to search for a file instead of entering its full path. When Pi finishes, review its response and any changed files. Use version control or backups for important work. For untrusted or unattended work, use a container or another sandbox. See Security.
在编辑器里输入 @ 可搜索文件，而不必敲完整路径。Pi 完成后，检查它的回答和所有被改动的文件。重要工作请用版本控制或备份；不可信或无人值守的场景，请用容器或其它沙箱。见 Security。

Continue later / 稍后继续

Pi saves sessions automatically. Exit Pi, then resume the most recent session for the same working folder with:
Pi 会自动保存会话。退出 Pi 后，在同一工作目录下用下面的命令恢复最近一次会话：
pi --continue
Use /resume to choose another saved session. See Continue or branch a session for session naming, branching, compaction, export, and sharing.
用 /resume 可以挑另一个已保存的会话。会话命名、分支、压缩、导出与分享，见 Continue or branch a session。

Uninstall Pi / 卸载

If you installed Pi with npm, run:
如果你用 npm 安装的 Pi：
npm uninstall -g @earendil-works/pi-coding-agent
If you used the installer, run it again and choose Uninstall Pi:
如果你用的是安装脚本，重跑它并选 Uninstall Pi：
curl -fsSL https://pi.dev/install.sh | sh
If you installed Pi with Nix, run:
如果你用 Nix 安装的 Pi：
nix profile remove pi
None of these methods removes configuration, credentials, sessions, or installed Pi packages from ~/.pi/agent/.
这些方式都不会删除 ~/.pi/agent/ 里的配置、凭据、会话或已安装的 Pi 包。
